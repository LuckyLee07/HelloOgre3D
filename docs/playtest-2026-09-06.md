# Sandbox19：Computer Use 试玩与体验改进（2026-09-06）

## 范围与方法

按用户要求，从玩家视角使用 Computer Use 操作当前 macOS Release 游戏窗口，实际执行右键点选、F/T/G 指令、观察面板切换和 Enter 重开。运行的是工作区 bin 下的游戏与 Lua 脚本，使用本地 app 包启动；普通试玩未开启 smoke 或 observation self-test，不以合成自测代替玩家操作。

这是一次针对个人 AI 实验场的可操作性检查。目标是让作者能理解战况、顺利发出指令并读懂反馈，不把外部玩家或发行指标引入阶段验收。

## 实际体验

| 环节 | 观察事实 | 判断 |
|---|---|---|
| 初次进入 | 6 秒准备后自动开战，默认大块 AI 观察面板覆盖右上战场；左侧状态和右下帮助字号很小、留白多 | 应优先解释玩家角色和目标，诊断信息按需打开 |
| 选择友军 | 空地右键后 Selected 变为 0；友军已在镜头外，此时 G 提示 no ally selected | 缺少简单可靠的选择恢复入口 |
| 下令 | T/G 能写入两名友军并出现目标绘制；8 秒后指令清理，但旧下令文案持续显示 | 操作响应存在，反馈没有清楚区分“刚发出”和“仍生效” |
| 集火 | 没有标记敌人、朝向范围内没有目标时 F 返回 no target in view | 应直接提示如何补救；朝向锥不等同于镜头可见范围 |
| 战况阅读 | 多次截图中主要看见指挥官和正前方墙体，队友与交火常在镜头外；雷达仍更新 | 视野与场景布局是更大的体验瓶颈；受移动工具限制，本次不判断主动移动后的体验 |
| 对局结束 | 原版第一局在第 2 波败北，日志 elapsedMs=143913；重开后的第二局到第 3 波，elapsedMs=200937 败北；第二局终局截图显示友军 0、指挥官仍存活 | 应解释是小队被消灭，结算时间不应继续增长 |

局部点击近处队友躯干也出现过清空选择，但角色正在移动且与指挥官重叠。本次不把单次现象定性为拾取算法缺陷，也不据此扩大命中区域。

## 已落地的改进

所有运行时代码修改集中在 `bin/res/scripts/samples/Sandbox19.lua`，未更改 C++、AI 行为树、物理参数或出生布局。

1. **Tab 全选存活友军**：即使友军在镜头外也能恢复指挥；复用现有选择函数，仅保存对象 id。空选择错误直接提示先按 Tab。
2. **默认隐藏 AI 观察面板**：I 随时打开/关闭，M1 显式观察自测仍自动启用面板和 trace。普通玩家初次进入先看到战场。
3. **更清楚的 HUD 与帮助**：采用 MediumMono，左侧面板由 370×190 改为 410×150；帮助为 430×210，写明三波目标、无武器身份、全选、标敌、8 秒指令规则。第一轮放大字体出现裁切，已根据实际截图缩短文本并调整高度，最终 1280×768 窗口检查完整显示。
4. **指令状态实时显示**：从现有意图快照读取有效指令数和最早到期时间；不重新做感知判断。无指令时明确显示自主 AI。
5. **反馈有时效、有下一步**：黄色提示展示最近操作，5 秒后回到选择或集火提示；集火无目标时提示右键标敌再按 F。有效指令仍由倒计时一行表达。
6. **更明确的结算**：显示小队被消灭或指挥官倒下的败因；记录结束时刻，HUD 时间停在结束时刻，Enter 重开清空结束状态。胜利分支说明已清完所有波次。

## 下一步体验任务

按依赖顺序推进，不同时铺开新系统：

1. **让交火更容易被看见**：独立检查第三人称相机、初始朝向和近墙遮挡，试验一个局部开阔出生区或可切换观察视角。验收：开局不动即可辨认至少一名队友和主要接敌方向；移动时不穿墙、不被 UI 遮住关键区域；仍可演示现有 AI 章节。
2. **队伍状态常驻可达**：若 Tab 全选仍不足，再增加两个队友的轻量状态入口，表达血量、选中与当前意图，支持单选镜头外队友。不要由此扩建通用编辑器。
3. **把失联推进机制变成可解释实验**：普通日志里仍出现 CONVERGE 和 FORCE_CONTACT；后者会重定位敌人，可能产生突兀接敌。先记录失联位置/持续时间，比较局部场地或出生点调整，再判断是否保留兜底。
4. **回到 M2 最小实验记录**：让每轮操作策略、参数和结果可复盘，区分自主胜负与指挥贡献。

## 验证边界

Computer Use 本轮提供的是瞬时按键、点击和普通拖动，没有持续按住 WASD/Shift 或右键拖框的明确 API。瞬时 W/D 未产生可确认的位移，因此不声称已经验收持续移动、冲刺、转向手感或框选；这些仍需可持续按键的交互验证。最终代码还把败因固定在结束时刻，避免结束后的伤害改变败因，并将无选择的 F 优先提示 Tab。未验证 Windows、其它分辨率及胜利结算分支的实际画面。这里的操作观察不等同于外部真人用户研究。
