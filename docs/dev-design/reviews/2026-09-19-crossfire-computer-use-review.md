# Crossfire：Computer Use 实际试玩评审

日期：2026-09-19。范围：体验诊断与优化建议，未修改玩法代码。此前右键/左键功能回归的 PASS 保留，本次记录其未覆盖的体验问题。

## 结论

当前可以完成鼠标操作，但玩家仍缺少判断行动后果的信息。最突出的缺口是：指定目标与实际命中对象不一致时，界面没有解释；关键指引会被普通操作覆盖；画面中看似可走的地面与实际接受命令的范围不完全一致。下一轮先做战斗可读性和点击反馈，并在同一个房间同时调整镜头、机器人与交火表现。

## 实际操作与证据

- 使用 `Crossfire-click-controls-20260919-v3`，macOS 普通原生窗口，内容区 1280×720；Computer Use 点地图、单位/名称/卡片、执行、暂停、下一关和重试。没有输入回放、强化夹具、预设自动通关或修改数值。
- 路线按屏幕上的空地和障碍选择；第三关重试复用原落点，先只改交叉攻击，再尝试移动解除僵持。操作者已知道既有规则，因此不是新手盲测。
- 原生窗口截图见本次 Computer Use 操作记录；日志与匹配汇总本地保留于 `tmp/crossfire-cua-review-20260919/`，不入库。日志确认 `background=false`，无 InputReplay、Lua 调用或 OGRE 异常。
- 工具操作有往返延迟；不根据点击间隔评价真人反应速度、极限操作手感或扬声器听感。

## 优化顺序

### P0：让命令、射界和结果说得清楚

1. **显示实际射线和阻挡者。** 选机/指向敌人时，从真实枪口预览到目标的射线，标记首个阻挡对象；规划模式保留“VEGA → 哨卫02”关系，显示可命中、正面盾、设备/单位/残骸阻挡。射线检查与实际子弹碰撞规则一致。当前仅 `CanSeeEnemy` 与距离通过，不能承诺子弹打中指定目标。
2. **持续无有效伤害时给出可操作反馈。** 连续几次被挡后显示“被哨卫01挡住，移动到侧面”，点击提示可定位阻挡处。自动射击状态也要区分有效交火与持续受阻。保持玩家决定换位/换目标，并保留实体挡弹规则。
3. **保留关键指引和目标名称。** 实测第三关暂停后，交叉目标提示变成通用的 TIME FROZEN，恢复又变成通用侧击提示。`crossHintShown` 只触发一次，关键指引因此可能永久丢失。战术提醒与操作确认分开，解决问题前保留提醒；首次连续挡弹可在引导开启时暂停一次、指示两台与对侧目标。`FRONT BLOCK` 应作为附加状态，不能替换 SENTRY 01/02 的名称。
4. **统一可见地面与可下令范围。** 点击首关掩体/中继塔表面会得到其后方的地面路线；第三关点击北侧墙内看似地板的位置却提示越界。当前鼠标逻辑直接投影到 y=0，并使用固定 `abs(x)<9、-11<z<10.5` 边界。需要命中预览、可达/不可达光标、明确的边缘标识，以及与场景/导航一致的范围。不要让玩家靠反复点击猜可操作区。

这组验收应能从画面回答：选中谁、命令指向谁、会先撞到什么、为何没造成伤害、下一步能改什么。覆盖原生鼠标、近塔/远塔、残骸、暂停/恢复与错误落点。

### P1：把画面重点还给战场与机器人

- **镜头与 HUD 一起重排。** 当前 1280×720 下，战场水平跨度约占窗口四成，机器人主体仅约二十余像素；左上品牌、左下教程/卡片、右下反馈、顶部执行相互分散。先以机器人显示尺寸增大约 1.4–1.5 倍做实机对照，收拢命令信息，检查 960×720 仍能看全有效战场和落点。
- **区分两机与路线。** 两台轮廓、颜色接近，路径也都是同样的细青线。给两机固定的色彩/形状标识，路径端点带编号；选中线路与未选中线路区分强度。图形与文字双重识别，避免只靠颜色。
- **强化护盾、侧击和死亡的视觉差异。** 护盾用可读的扇面/朝向，挡弹与有效命中使用明显不同的火花和血条反馈。第三关两个 FRONT BLOCK 标签会连成一排，VEGA 标签还会重叠；需要避让和稳定的名称。被击毁的哨卫和机器人目前保留完整外形，残骸应有明显损毁/熄灯状态，并和仍存在的碰撞体一致。
- **中文操作与因果提示。** 关键指令、选机、自动开火、暂停/执行和失败原因直接放入游戏内中文 UI；首次教学按“选机→落点→执行→看到有效侧击”推进。二、三关教各自的新问题，避免重复首关三段路线提示。需要可用的中文字库接入，不能把中文字符串直接塞入现有 ASCII 图集。

验收重点是暂停截图也能辨识友军、敌军、残骸、护盾朝向与目标关系；在动作过程中能看出一次指令带来的差异。以上视觉工作和 P0 在同一个房间联合交付，不将美术推迟到关卡功能之后。

### P2：让短局有清楚的决策与复盘

- 前两关本次约 10 秒仿真结束，大部分主动操作发生在开局。定位继续收敛为短局战术解谜，设计一次清晰的二次决策，例如暴露射界后重新指定目标；调整时首先验证反馈是否给足理解时间。
- 失败页展示本局具体原因：例如“88 次射击被正面盾挡住、0 次有效侧击”，标出相关单位与可调整的站位/目标。第二次失败应区分近塔遮挡、损失队友与换位后阵亡，而不总是同一句换角度。
- 后续场景精修围绕战术可读性：冷却区的遮挡通道、联锁区的交叉射界成为构图重点，再补材质层次和局部环境动态。当前三关虽有布局差异，平背景、统一底盘和相近设施让空间身份仍弱。

## 建议下一轮的范围

先集中在一个房间完成“镜头放大 + 两机识别 + 地面落点预览 + 攻击射线/遮挡提示 + 稳定中文引导 + 护盾/命中/残骸表现”，再用第三关的两次失败路径复验。首个目标是让玩家只看游戏画面即可理解失败并作出有效调整。之后再评估三关节奏与场景深化。

本轮没有修改代码、关卡数值、资源或试玩包；上述均是待实施项。保留前两关实玩成绩与第三关失败事实，不把历史自动通关当成本轮三关都通关。
