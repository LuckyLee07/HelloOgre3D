## 当前判断

Crossfire 已具备完整的三关可玩闭环和可用的技术验证基础；距离“精致的小玩法”的主要差距，转向整体美术质量、战斗信息的直接表达，以及值得重复尝试的决策节奏。现有证据不足以给出“完成度百分比”，也不能把通关和测试通过当成体验已被作者认可。

这份评估基于最新代码、v6 实机画面及上一轮原生操作记录。主要方向沿用[联合设计](../specs/2026-09-19-relay-microgame-design.md)；构建、三关、失败、查询与原生冷却区证据见[本轮实施记录](2026-09-19-crossfire-motion-finish.md)。没有重新启动一轮试玩，也没有做扬声器听感或可靠帧时间测量。

| 方面 | 已有事实 | 当前差距与判断 |
|---|---|---|
| 流程与操作 | 选关、左键下令、暂停/两秒推进、目标指定、受阻定位、报告/重试和记录保存均可运行；原生冷却区两机存活通关 | 操作入口已基本完整，接下来应减少查读和注意力切换；仍需作者确认顺手程度 |
| 场景与角色 | 31 个原创网格、三种场景表面、双色异形机器人、阴影、供电变化和冷却风扇 | 主会话的视觉判断：大面积重复地砖与浅色设施边缘较抢眼，机器人在最终机位下体量偏小；新增细节未充分转化为清晰主次和材质区别 |
| 战斗表达 | 真实枪口/命中、方向盾、蓄力/锁定/三连发/冷却、四种事件特效及轻微后坐都已存在 | 多种战术射线和文字标签同时占据交战区；敌方标签目前主要显示护盾说明，蓄力与冷却未充分表现在主体上。正常速度下辨认伤害原因的难度仍需验证 |
| 决策与内容 | 三关依次使用分路侧击、设备遮挡、双塔交叉目标；敌人正面盾和残骸挡弹产生真实后果 | “分好路后等待自动交火”的风险仍在，当前通关记录不能证明重玩动机；也未证明存在多个有意义的解法 |
| 声音 | 已有八路有限并发、优先级/声像和合成短音；不是单路音效基础设施空缺 | 缺有声实玩验收；不能凭生成器或播放日志判定声音好听，也不能先断言必须重写音频后端 |
| 工程与平台 | 新 macOS arm64 Release、旧 sample 入口、三关与生命周期验证通过；特效固定 28 槽，三关实际峰值 6/5/8 | 本版 Windows、连续帧性能与较长时间重试尚缺对应证据；12 秒入口 smoke 不等于旧 sample 整场验证 |

## 推荐顺序

### 第一轮：首关的画面与战斗表达联合精修（最高优先级）

目标：在实际游戏镜头下形成一个可重复使用的美术与交互基准。范围限定维修庭院，角色/材质/场景/HUD/交火同轮交付；三关共用资源的变化同步检查其他两关。

| 任务 | 具体产出 | 主要文件或职责 |
|---|---|---|
| A1 构图与界面层级 | 保留两机、待执行命令、执行/暂停和下一步操作的明确入口；减少顶栏、底栏、单位标签中的重复说明。默认突出选中单位、当前危险和实际阻挡，必要信息可主动查看。首用引导不得因“简洁”消失 | `crossfire_hud.lua`、`crossfire_feedback.lua`、`Sandbox20.lua`；`crossfire_scene.lua` 相机安全区与地面拾取联调 |
| A2 主体与材质基准 | 成套精修双机、哨卫和首关核心设施的轮廓/比例/材料分区；先让单位在真实画幅中清楚，再做接缝与小零件。场景降低边框/重复纹理的竞争，建立主体、行走地面、背景的明暗层级 | 资产生成器或明确可重建的建模导入源、模型 SOURCE/manifest、`crossfire.material`、`crossfire_scene.lua` |
| A3 可见的攻击节奏 | 复用现有蓄力、锁定、开火和冷却事实，让哨卫的炮口/机体信号与危险提示表达阶段；区分规划路径、当前射界和敌人威胁的形状/出现条件。护盾挡弹、实体遮挡、有效命中和击毁在正常速度下可辨 | `Guard.lua`、`Sandbox20.lua`、HUD/Feedback/Effects、RenderComponent；首轮优先保持数值与判定 |
| A4 同一事件的声音核对 | 实际听选中/下令/开火/盾挡/机体命中，比较声画时点和并发层级，记录需要替换的声音；先使用已有八路后端 | `generate_crossfire_audio.py`、RuntimeUiSound、Sandbox20 音频调用；未实际听到的项目继续标未验 |

依赖：A1 先定镜头与画面占用，A2 在该画幅制作；A3/A4 使用同一份真实事件和状态。UI 改动必须让小窗口仍能点地图、辨认单位与执行，不再退回“点击无反应、不知怎么开火”的问题。

资产策略：现有 base material 已提供法线图和高光参数，先做一组实际材料小样并验证 GL/D3D9 的语义，再决定是否补局部 shader；不预设已有完整 PBR/粗糙度流程。程序生成可继续承担重复模块，但主体必须按最终画面审视。如果一轮成套精修仍不能改善造型，应改用专门建模/统一资产导入方式；具体资产、许可和可能费用另列候选，当前没有采购或工具安装需求。

验收产物：同一分辨率/镜头的 v6 与新首关对照；实际开局、交火、收复三个阶段的截图，以及包含移动、转向、点射、盾挡、受击、击毁、暂停恢复的一段连续战斗。原始媒体仅留 tmp。

退出条件：720p 下无需放大截图就能区分双机、看出敌人朝向和攻击阶段；暂停规划与共同执行入口持续清楚；正常交火中能区别挡弹与有效命中；文字/遮挡/点击/物理回归通过。作者对模型、场景、交火分别评价，最弱项仍明显时留在本轮修正，不靠扩关抵消。

### 第二轮：三关的策略节奏与重试价值

在第一轮的表现基准稳定后，核对“看懂威胁 → 做一个选择 → 看见后果 → 能改进下一次”的过程。先调现有位置、前摇、转向承诺和冷却窗口，不预设添加技能、成长或新敌人。

- 第一关验证：分路确实让夹击原因可见，首次选择后有及时结果；提示解释侧击而不是要求照抄固定坐标。
- 第二关验证：设备遮挡在行动前可理解，换位收益在下一段执行中可观察；复用当前射界查询，不声称预测未来必命中。
- 第三关验证：交叉目标、分批处理或再次换位的得失能被解释；是否至少有两种可行安排需要实验后确认，不能先把“多解”写成已完成。
- 选取正面进攻、分路侧击、受阻后换位三类路线做小规模同条件对照，记录存活/损伤/有效侧击和无效等待。行为有波动时看原因，不用某一次最优通关秒数作为唯一平衡目标。
- 复盘优先给出可执行的一条建议，继续区分实际弹丸命中与射界快照统计；保留作者自由重试和两秒推进。

主要修改面：`crossfire_encounters.lua`、`Guard.lua`/`Move.lua`、`crossfire_review.lua`、HUD。决策继续复用现有 BT/Blackboard；真实命中与位置以物理为准。验收同时覆盖普通鼠标操作与内部回放，首次理解和是否愿意重玩由作者体验验证。

### 第三轮：统一三关品质并收口版本

将首关认可的造型/材质/交互语言推广到另外两关，保留维修、冷却、联锁的设施与战术差异。补声音弱项、标题/选关/结算的统一表现，并完成可独立运行的版本。

- 若听感证明需要持续环境或机械声，先确认已有后端缺少的能力。当前 PlayLayer 是短音接口；持续声的句柄、淡入淡出、暂停与退出生命周期应由 runtime 管理，不在 Lua 用反复触发短 WAV 模拟无限循环。新增导出须同步头文件、导出声明/局部绑定和 Lua 调用点。
- 以固定机器、版本、分辨率和路线建立连续帧时间基线，覆盖交火峰值和切关；优先定位可感知卡顿。正常交战 60 fps 可作为候选预算，当前并无证据承诺达到；截屏开销与正常运行分开测量，沿用 Tracy。
- 复核重试/切关/失焦/设置保存、资源缺失与异常退出的可诊断性；按变化选择最小充分回归。若共享 C++/接口变化，按验证工作流补旧 sample。
- macOS 与 Windows 分别构建/运行；共享材质、输入、音频语义在相应平台验证，缺 Windows 会话时明确保留未验，不阻断可完成的 macOS 工作。

产物是可试玩的三关版本、已核实的运行边界和精简说明，不以商业发行、外部玩家或完整编辑器作为结束前提。

## 本阶段暂缓项与调整依据

暂缓增加关卡数量、角色职业/技能树、养成、随机地图、完整回放编辑器和无证据的引擎迁移。已有 AI 研究模块继续保留，M2/M3 可按个人兴趣独立认领，不作为 Crossfire 精修的前置工程。

以下证据会改变顺序：点击/命中出现真实回归则先修正确性；材料小样证明现有渲染无法达到目标则单列最小渲染缺口；完成画面表达后仍只有一种机械重复操作，则优先调整核心遭遇规则；真实听感或连续帧测量发现主导问题，则在对应轮提前处理。
