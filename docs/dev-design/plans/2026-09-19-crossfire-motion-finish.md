# Crossfire 动态场景、战斗特效与收复演出

状态：本轮实施与 macOS 验证完成；作者主观体验验收保留。用户已授权提交上一轮并继续升级；上一轮本地提交为 `0d44f5f`。继续沿用[双机小玩法设计](../specs/2026-09-19-relay-microgame-design.md)，本轮解决静态设备、线段式开火反馈及结算立即遮住战场的问题。

## 实施范围

- 场景/资源：为冷却设施增加克制的风扇运转；收复后供电按短序列点亮，失败即时熄灭。新增视觉面不参与物理或导航，旧碰撞网格不变。资产代理负责生成器、场景模块、材质及来源说明。
- 战斗表现：用项目自制透明图和有容量上限的视觉面池替换枪口/命中/摧毁的临时调试线；护盾、有效命中和摧毁各有区分。只响应实际发弹/命中/死亡，不制造虚假击杀或贯穿弹道。独立代理负责效果模块，主会话负责事件与生命周期集成。
- 运动/收尾：机器人既有悬浮/倾斜/后坐做小幅调整；胜负先保留战场约 0.9 秒，显示简短结果横幅，之后展开复盘；Enter 可直接展开，不会误切关。游戏立即冻结，战斗计时/成绩不受演出影响。
- 时钟：GameManager 给既有 `Sandbox_Update` 追加第二个纯值 UI delta 参数；旧 sample 忽略额外参数。普通规划时战斗特效/风扇冻结；结果阶段只有视觉收尾可继续。无新绑定、无类布局变更。

## 集成与验证

主会话独占 Sandbox20、HUD、字体生成、C++、构建、运行窗口和打包；资产及效果模块可独立并行，不同时操作共享 bin 或运行游戏。不新增关卡，不改敌人 HP/射速/护盾、刚体/导航与 AI 决策。

验证：Lua 5.1、资源确定性与原碰撞几何；效果池复用/过期/重试/切关销毁后引用检查；结果阶段输入与 960×720 排版。当前平台 Release 构建与 Sandbox6/7/8/19 回归；三关、短步推进、查询、胜负/重试实际窗口；Computer Use 原生交火及收复过渡。动态验收使用可比时刻画面与日志，不以静态截图代替动画观感。Windows 和扬声器听感仅在实际执行后标验证。

## 原生试玩与交付

普通 1280×720 原生窗口，无 InputReplay、无夹具：标题选第二关，鼠标点两侧地面路线，点击“推进 2 秒”并用 E 分段执行；场景风扇随执行旋转，规划时保持相位，机器人绕行后自动交火。该会话途中包含额外鼠标改令，重新确认两侧路线后完成；不把它作为固定路线性能基准。六段自然到期各推进 2013 ms，最后一段因胜利结束。实际通关 13.200 s、两机存活、72 损伤、18 侧击/18 盾挡。截图观察到摧毁火花与底部“中继站已收复”横幅同帧出现，前场先亮；924 ms 后显示完整报告，前后仿真 tick 均为 13233。报告时效果峰值 5、89 次事件、81 次复用、0 淘汰、active=0。R 重试后风扇/供电恢复初始状态，没有遗留火花。
