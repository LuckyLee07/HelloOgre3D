# Sandbox19 中继站状态反馈收口

日期：2026-09-12
状态：暂停（核心战斗体验优先）

## 目标

让任务阶段不仅存在于 HUD 文本中，也由场景内的中继站清楚表达。玩家应能从正常跟随镜头辨认待命、交战、前进、集合、成功与失败状态；反馈必须克制，不遮挡角色、路线或目标标记，也不能改变碰撞、导航和 AI 视线。

## 设计与职责

- `sandbox19_scene.lua` 创建并持有只渲染的门面光晕、桅杆信号、庭院入口提示和集合区提示；`Scene.UpdateRelayFeedback(state, wave, timeMs)` 把既有任务状态映射到视觉状态，不重新推导玩法规则。
- 琥珀色表示未完成、交战或前进，青色表示可以集合或已完成；失败关闭信号。动态脉冲使用仿真时钟，因此暂停与结算冻结不会产生脱离游戏状态的动画。
- `sandbox19_relay.material` 复用现有 `relay_overlay` 的 GL/HLSL shader 和项目自制软遮罩贴图，提供少量离散亮度档。运行时只在档位变化时切换材质，避免每帧创建材质或对象。
- 所有新增形状来自 `CreateVisualPlane`，没有 Bullet 刚体，不参与 navmesh 或射线。现有 relay 实体信标只切换材质，不移动几何。
- `Sandbox19.lua` 在任务更新后同步视觉状态；产品 fixture 按 PREPARE、WAVE、ADVANCE、REGROUP、VICTORY、DEFEAT 断言映射，证明表现没有与玩法阶段脱节。

## 验证

- Lua 语法、材质脚本加载、产品 fixture 与 Sandbox19/6/7/8 回归。
- macOS arm64 Release 真实窗口抓帧，分别检查琥珀交战态、青色集合/完成态的可见性、透明排序和 HUD/UI 隔离。
- 重跑导航与真实碰撞断言，确认纯渲染反馈没有改变两条路线、出生点或子弹遮挡。
- Windows/HLSL 当前只能做材质路径静态核对；没有对应平台会话时保持 NOT RUN。

## 完成条件

- 任务每个阶段都有唯一、可断言的 relay 反馈模式；重开恢复待命态。
- 正常镜头能看见信号但不会形成大面积高亮幕布，暂停/结算、HUD、目标标记与角色可读性不回归。
- 产品 fixture、相关 sample、构建/运行和文档同步均有当前改动后的证据。
