# Sandbox19 第二轮体验优化：前方视线与接敌布局

日期：2026-09-06。前置提交：`0f998c2`（项目方向与试玩文档）、`6ab7fb4`（M1 与首轮操作反馈）。本轮在这两个本地提交之后独立修改。

## 目标与取舍

让站在初始位置的玩家能看见友军和接敌方向，减少高墙、坡道和高台让战斗长期发生在镜头外的情况。采用局部场地与出生点调整，保留第三人称跟随、坦克式转向和原有指令/AI 决策，不在这一轮扩建通用镜头系统。

再次用 Computer Use 启动已提交基线，42.5 秒截图仍主要呈现指挥官与前方高墙，雷达显示单位而主视野没有交火。代码对应原共享关卡的正前方高墙、坡道、高台以及分散的出生点。

## 实现

- Sandbox19 改为专用开阔场地：12 个 16 米立方体拼成顶面 y=0 的连续平台，范围 x=-24..24、z=-24..40。
- 中央 x=-6..6 通道留空，四组 2 米高掩体放在两翼（x=±10，z=8/10 和 22/24）。角色仍有绕行与遮挡场景，但开局相机到主要接敌区之间没有高墙。
- 指挥官出生点 `(0, 0, -6)`；友军在前方两侧 `(-3, 0, 1)`、`(3, 0, 1)`。敌人从前半场 `x=±5,z=18` 或 `x=±7,z=25` 出生，并朝向 -Z。
- 所有出生位置继续经现有导航投影和物理位置接口落地，不直接修改渲染位置。
- 原 `SandboxUtilities_CreateLevel` 保留，其它 AI 章节的场地不变。沿用原波数、敌人数、伤害、血量与失联兜底规则。

第一版用长方体做平台和掩体，截图出现高于掩体的竖直薄片；最终改用原项目已验证的立方体生成路径，复测薄片消失。没有据此改动第三方生成器，也未宣称已查明其全部根因。

## 验证设计

新增仅 smoke 模式启用的出生点检查：对遭遇战实际使用的出生槽位，检查最近导航投影距离小于 1 米，并能从指挥官出生点寻路到目标、路径终点距离小于 1 米。不是只检查 FindPath 返回 true，以免把不完整路径当作成功。

初次自测暴露两个边界并修正：

1. ConfigManager 对表做递归合并，较短的出生点数组仍残留默认数组尾部。检查按友军数量与各波出生模式收集实际使用槽位；没有改动全局配置合并语义。
2. 开阔场地首帧即可接敌，而观察器刚刚启用 trace。M1 自测在原超时窗口内等待 traceFrame 大于 0 后再验证真实自主行为，保留指令目标、分支、记忆、TTL、死亡和重开的原断言。

## 当前限制与后续

这轮改善了出生视角的场景遮挡，不等同于实现了通用镜头碰撞：贴近两翼掩体、转身后镜头进入物体等情况仍需持续移动验证。Computer Use 的瞬时按键不足以验收持续 W/A/S/D、冲刺和右键拖框，本轮仍不宣称这些已通过。

视野开阔后，敌人更早能接敌，指挥官也更暴露，实测对局明显更短。没有充分证据认定指挥玩法更平衡或更有趣。下一轮宜先在可持续移动的条件下体验退后/绕掩体，再围绕波间集结、后续波次的安全出生距离做小规模对照；不要直接用降低伤害掩盖站位问题。

平台边缘仍是可跌落边界；本轮没有增加通用防跌落或导航预算。胜利流程、Windows 和其它窗口尺寸不在本次实际画面验收范围。
