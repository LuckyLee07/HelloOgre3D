# 实施与按需并行

供 [共享工作流](workflow.md) 的复杂实施阶段使用。简单任务由当前 agent 完成。

当工具和当前权限允许、任务存在具体独立子问题且主会话有可同时推进的工作时，可委派子代理：例如独立模块实现、只读调用链核对或风险较高改动的独立 review。不强制每 task 三轮 agent，不因工具不可用而停止。

- 默认继承当前模型与推理设置；不硬编码 haiku/sonnet/opus，也不擅自切换用户选择的 GPT-6 Astra。
- 简报给目标、边界、必要源码/设计链接、负责的文件、验收与依赖；让执行者按需读相关计划，避免复制整个会话。
- 无写入冲突且无逻辑依赖的子任务才并行。共享 build/bin、生成绑定和运行窗口由主会话串行协调，防止覆盖产物。
- 子代理回报改动、验证证据和未解决项，不自行提交或清理别人工作。主会话核对最终 diff、需求覆盖、所有权/生命周期/平台风险并整合验证。
- review 必须基于已完成的目标改动；仅在风险或新发现值得独立上下文时追加 reviewer。
- 失败后补上下文、修方案或缩小问题；没有新信息不原样重派。已有实现授权下连续推进，关键阻塞才询问。

完成条件由 [verify.md](verify.md) 和用户目标决定，不以代理报告 DONE 代替证据。
