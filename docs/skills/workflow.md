# HelloOgre3D 共享开发工作流

本文件是 Codex 与 Claude Code 的流程真源；各 SKILL.md/命令仅路由到这里。项目约束见根 `AGENTS.md`，节点按需读取。路径均相对仓库根目录。

## 选择范围

| 用户意图 | 执行方式 |
|---|---|
| 小修、文档修改、明确局部实现 | 定位 → 修改 → 相关验证 → 必要文档同步；无需 spec/plan 文件 |
| 设计、探索或只要计划 | 按请求产出设计/计划，完成该交付即结束，不自动实施 |
| 跨模块功能或明确要求设计并实现 | 简短设计与计划 → 实施 → 验证 → 文档同步，已有实现授权持续有效 |
| 明确要求 gated workflow/逐阶段审批 | 写可审阅 spec 后等 Gate 1；写 plan 后等 Gate 2；不额外逐节确认 |

显式 `/hello-develop-design` 或 `$hello-develop-design` 使用本流程，具体交付范围从描述及上下文判断；调用名称本身不授权提交。没有描述但上下文已有目标时沿用它，完全缺少目标才询问。

## 上下文与续跑

1. 检查工作区状态并读取尚未加载的 `AGENTS.md`、记忆索引。方向性功能读 `docs/project-direction.md`。
2. 用 `docs/registry.json` 的 source_paths/name/tags 定位模块，读取相关 doc_path 与源码；related_docs 只在具体问题需要时打开。命中数量不触发审批，零命中时用源码和 `docs/README.md` 自行定位。
3. 续跑以当前目标、用户指定计划、任务记录和实际 diff/验证证据为准，不按“今日草案”自动选任务。多个候选确实无法区分才问；不自动 restore、删草案或重写历史。
4. 缺少可选索引/节点时用可用源码与约束继续，说明缺口；必要需求缺失才暂停依赖它的工作。

## 按需节点

- 需求或方案需澄清：读 [brainstorming.md](brainstorming.md)。有实质取舍才比较方案，不强凑数量。
- 跨模块实施、长期工作或用户要求计划：读 [writing-plans.md](writing-plans.md)。保留目标、依赖、验收及剩余工作，步骤颗粒度由风险决定。
- 进入实施：小任务直接完成；可独立并行的复杂任务可读 [subagent-driven-development.md](subagent-driven-development.md)。分派不能替代整合验证。
- 根据最终改动面读 [verify.md](verify.md)，共享构建/bin 的操作串行；同一批改动可合并构建和去重回归。
- 同步因本次改动失真的文档：读 [doc-sync.md](doc-sync.md)，属于任务收尾，无固定 Gate 3。
- 用户要求提交时才读 [gitcommit.md](gitcommit.md)，保留既有授权，不默认逐 task 提交或 amend。

## 停止与交付

已知问题继续定位修复，有新证据再重试；必要权限、外部依赖或关键需求阻塞时暂停相关动作，完成其余独立工作。不得把跳过必要验证的实现记成已完成。

报告结果、关键改动、实际验证与未验证项；有 spec/plan 则链接并更新状态。状态可用“草案”“执行中”“待验证”“受阻”“已完成”；只有用户实际批准才写“已批准”。历史计划的旧状态仍可读取。
