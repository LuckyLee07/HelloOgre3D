# 实施计划

供 [共享工作流](workflow.md) 在跨模块、长期任务或用户要求计划时使用。

从目标和已有设计列出职责、文件、任务依赖及可观察验收。用可独立检查的结果划分任务，不规定每步分钟数，不复制整段实现代码或预设每步 commit。

需要持久记录时写 `docs/dev-design/plans/<YYYY-MM-DD>-<topic>.md`：目标、设计链接（如有）、状态、任务清单。每项给出相关文件/层、预期行为、依赖与验证策略；跨语言接口任务显式列出头文件、导出声明、绑定和调用点同步。

验证采用 [verify.md](verify.md)，允许同一改动批次共用构建和去重 sample。计划不应承诺当前平台无法提供的验证。

自审需求覆盖、所有权/接口一致性与可执行性；已知未知项写清如何查证，不用猜测填满模板。执行时以新证据修订计划，用户最新要求保持有效。

只要求计划则在计划交付后结束；已授权实现则继续。仅显式 gated 模式等待 Gate 2。
