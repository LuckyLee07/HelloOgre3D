# Crossfire 原创工业微缩资产

日期：2026-09-19。对应 Sandbox20 的维修庭院、冷却区与联锁区三场战术遭遇。

本目录网格由项目脚本 [generate_crossfire_assets.py](../../../tools/generate_crossfire_assets.py) 构造；仅复用 [generate_relay_meshes.py](../../../tools/generate_relay_meshes.py) 的 Ogre v1.100 序列化与基础面片工具。本目录未使用外部模型或贴图，没有人体骨骼或动画依赖。表面 PNG 由同一脚本用标准库、明确的栅格图元和固定数学参数生成，源代码即为可重建源图；不依赖随机种子、AI 图片服务或第三方图片。UI 另使用 OFL 授权 Noto 字库，见[字库说明](../../fonts/crossfire/README.md)。材质见 [crossfire.material](../../materials/crossfire.material)，使用既有 `base_material` 的 GL3+/D3D9 shader 与白色/平法线基础纹理。

## 造型与材质

灰钢环境涂层、冷蓝灰面板和石墨机械接缝形成背景层级，较亮的单位釉面与金属形成主体；青色用于己方及设施信号，钢蓝用于第二台机器人识别，橙红用于敌方护盾。机器人通过真实轮廓、两枚中空涵道、悬挂支架、独立枪口、传感器面和实体数字笔画形成识别，不套用 Soldier 模型。护盾哨兵使用分开的两片护盾、中央炮口通道、后侧散热弱点与三支落地支撑。环境共用切角、倒角、层状板缝、径向机械和窄灯带语言。

新增四条独立维护边界，内沿对应 x∈(-9,9)、z∈(-11,10.5)，设备/边界有可读表面类型用于鼠标拒绝反馈。死亡时 Crossfire/Wreck 熄灭亮色并保留原刚体；盾向扇带的120°与物理规则一致。

实体材质为不透明表面；`Signal`/`EnemyLight` 是亮色涂层，在当前基础 shader 中没有独立发光或透明护盾语义。地板色彩图仅保留克制的低频色差，去掉每块地砖重复的划痕/固定件；维修位保留独有的局部补板和轮迹。环境与单位涂层分别使用独立材质和图片引用；没有用颜色图冒充法线或粗糙度图。无碰撞检修标识与供电灯条使用现有跨平台 `relay_overlay` shader、透明 PNG 和深度检测，不投影；供电亮色是自亮状态面，不产生虚构的照明光池。

`deck_marks.mesh` 只包含图案本身，没有透明图、背景面或额外地板。优先作为不参与碰撞/导航、关闭投影的视觉模块，稀疏放在两翼通路和前景；不需要对每块地砖重复。若使用薄刚体，单凸包会连接全部图案的空区，不再具有镂空碰撞语义。`base.mesh` 置于 `(0,0,0)` 即与中心为 `(0,0,0)` 的 20×24 地砖场地衔接，不要再整体向下移 0.24 m。

这些网格保留多 submesh 材质，装配时不要用整体材质覆盖抹平分区。机器人枪口为无骨骼的局部坐标，必须随真实对象转向变换；视觉悬浮/后坐不应反写物理位置。

`gate.mesh` 门洞不是一个凸形物体，不能以整网格的单一凸包制作可通行门口，否则门洞会被碰撞封住。首版可用作不可达背景；若作出口，应为两柱和顶梁配置各自碰撞。`core.mesh` 的细管、灯带及门厅细节不代表额外可通行或可穿透语义；游戏碰撞/视线轮廓需由装配层独立明确。

## 三场空间装配

[场景脚本](../../../bin/res/scripts/samples/crossfire_scene.lua) 的 `Scene.Create(index)` 按三关值合同装配：维修庭院保留中央 `(0,0)` 核心与原两翼掩体，后景以单接收碟塔配双冷却筒；冷却区把核心偏置 `(-2,0)`，两枚真实冷却筒与纵向掩体改变进路，后景使用四筒设备组；联锁区采用 `(-3,0)/(3,0)` 双核心、中央分隔掩体及双塔轮廓，两条外侧路线保持开放。门厅编号和地面编号分别为 07/08/09。

场景只在当前庭院中缓存供电显示平面的 Block 引用；调用方销毁旧庭院后，`Scene.Create` 立即丢弃这些引用，重建同名 default NavMesh，并复用一个由场景管理器拥有的光源。相机为偏航 178°/俯仰 -42°，按实际投影拟合 HUD 安全矩形；操作区及完整机器人均参与尺寸约束，不通过仅缩放外壳改变碰撞外观。后景支撑台最远约 Z=15.89，180 m 视觉背景平面不参与导航。中空碟面在物理中是整体凸包，放在后墙外而不作为可交战掩体；部分后景塔身沉入服务底座以保证固定镜头下的轮廓和 HUD 不重叠，不修改可行走地面。

## 表面区域与收复状态

同一地板的四块嵌板现在使用 `deck_panel.png` 的低频表面变化；三种材质变体只改变颜色/高光参数，不改变几何。维修场以不对称暖灰维修位和补板/轮迹为特征，冷却场以沿冷却筒展开的青灰区块、环形检修标识为特征，联锁场以双核心下的成对蓝灰区块和两组实体间回路印刷为特征。行动地面不添加高频噪声或密集高亮线条。

`Scene.SetOutcome(nil)` 恢复暗琥珀待机和风扇初始角度；即使当前也是 nil，同场重试仍复位风扇且不重复打印状态。`VICTORY` 开始一次 900 ms 供电序列：最前端 6 条立即点亮，其余按实际 Z 从前到后依次切为青绿，最终到达后方冷却设施；重复 VICTORY 不重启序列。`DEFEAT` 立即熄暗并冻结。状态变化只替换当前场景的无碰撞显示平面材质，不重建刚体或导航，不改设备位置。沿左右边缘设置的指示灯在中央结算面板出现时仍能看到。

`Scene.UpdateVisuals(simDeltaMs,uiDeltaMs,screen,paused)` 的时间由调用方提供。只有 `screen=="battle"` 才更新；菜单需要传非 battle 的 screen。正常执行阶段以 simDeltaMs 驱动风扇，普通规划暂停、标题和菜单冻结。胜利阶段使用 uiDeltaMs 完成最多 900 ms 的供电与短暂风扇收尾，此后不再更新；失败全静止。不读取系统时间、不按帧伪造时间，也不修改战斗计时。仅在序列完成时打印 `[CrossfireScenePower] elapsedMs=900 lit=... total=...` 一次。

每个冷却筒新增一个 1.50×1.50 m 的无碰撞顶面，位置为设备局部 `(0,2.837,0)`、材质 `Crossfire/FxRotor`。自制三片宽叶片以 36°/s 旋转，深色圆形底面覆盖旧网格的静止叶片显示；真实中心轴与外壳仍从原网格透出。显示面低于已有 Y=2.845 的顶部状态环，二者不争同一平面，原有刚体与导航网格完全不变。三关分别 2/6/2 个风扇；切关 Create 清除所有旧显示对象引用。

## A2 主体与材质精修（46d7fd2 之后）

本次不增设施、不移关卡、不改相机。环境使用独立的 `Structure` / `StructureTrim` 灰钢涂层、`FacilityTeal` / `FacilitySignal` 设备色和 `SafetyPaint` / `Wayfinding` 标识色；只在明确列出的环境 builder 中重映射。机器人不经过这些重映射，保留 `Vega` / `Rook` 高识别色，新 `ActorTrim` 为偏冷浅釉面、`ActorMetal` 为更集中的金属高光。环境 `structure_coating.png` 与旧单位涂层图分开，未改变共享 base shader 或声称采用 PBR。

地面 `DeckJoint` 抬高最暗缝隙色值以降低黑色网格对比；`deck_panel.png` 去掉成排重复长划痕和角部固定件，只留下低频色差。三种区域板的色差也收敛，仍通过原有布局、维修补板、冷却环和联锁线路区分。边界实体几何与可走内沿完全未变，奶白顶条改为中明度的环境材质，不占用单位的最亮层级。

- VEGA：原包络内扩大连续楔形顶面，增大白色 V 标记，前肩略抬高；将两侧六枚微小散热片改为两块较大的进气口。枪口沿原轴线，外壳更清楚但挂点不变。
- ROOK：更平直、宽大的顶面和前肩，扩大双条顶面标记；金属涵道与蓝色机壳分开，不再全部压在暗灰中。删除同样的细碎散热片。
- 哨卫：在原包络内补足红色前肩的可见顶面，中央顶面改为深灰陶瓷及较宽的浅色前向箭头；收窄盾面常亮信号条，让动态蓄力信号承担阶段提示。原三脚、双盾和枪口位置保留。
- 核心：几何完全保留，只建立石墨内筒、灰钢立柱、较亮上冠和低饱和管线的三段材料层级；原状态灯环依然由场景控制。较亮上冠是设施自身的视觉重点，立柱不再与单位争大块奶白色。

所有 31 个网格 bounds 与基线逐轴一致。3 个角色改变了包络内的顶点：`drone.mesh` / `drone_b.mesh` 的三角形数为 2412 / 2488（各减少 176），`sentinel.mesh` 为 1848（增加 64）。其余 28 个静态网格的完整顶点及三角形集合与基线相同，包括 core 和四种 tile；仅材质名/分组改变，因此 Bullet 凸包源与导航三角形不变。精确尺寸、三角数和新 SHA-256 见 manifest。

角色物理仍由 `AgentFactory::CreateAgentWithProfile` 的固定盒体提供：机器人 1.3×1.4×1.5 m，哨卫 1.8×1.6×1.9 m；机器人既有视觉偏移 `(0,.25,0)` 保留。新顶面与肩甲都在这些盒体范围内；继承的涵道边缘/外露枪管在局部超出盒体，但它们的整体最远包络和真实枪口 `(0,-.02,.90)` / `(0,.20,1.12)` 均未扩大或移动。没有按视觉缩放碰撞，也没有把动态表现反写到物理。

供主流程使用的新武器阶段材质为 `Crossfire/Charge1..4` 和 `Crossfire/Cooling`。前者使用 `fx_charge.png` 的橙金粗断环、向心短条与暖白中心，按充能进度 **1 弱 → 4 强**，alpha 为 `.25/.50/.75/1`，与 Fx1..4 的衰减编号相反；后者使用 `fx_cooling.png` 的偏白青的三根分离粗短横条。均 256×256 RGBA、中心 UV(.5,.5)、现有 overlay shader、双面、深度检测/无深度写入和干净透明边缘。主流程把它们装在真实枪口周围的 .9×.9 m 无碰撞小面上，材料本身不推断攻击阶段或触发开火。

离线比较已核对全部 bounds、28 个静态网格顶点/三角形、角色枪口元数据及材质引用。CPU 深度预览只用于查看主体大色块和方向轮廓，不能作为最终 GL、720p 主次或用户美术验收。

## 冷却与联锁设施材质、区域牌（f0bbb9a 之后）

本轮只重新划分现有设备的材质，不移动、缩放或增加静态几何。`cooling_stack.mesh` 的筒身使用灰蓝 `CoolantCasing`，纵向支架与风机叶片使用深色 `FacilityFrame`，顶冠与金属束环分别使用 `CoolantCrown` / `FacilityMetal`，外管使用低饱和 `CoolantPipe`。`relay_tower.mesh` 的接收碟使用浅灰 `DishCeramic`，支撑桁架为深色 `FacilityFrame`，底部机柜为中灰 `RelayCasing`，金属圈与基座关节使用 `FacilityMetal`。陶瓷碟与设备顶冠均低于单位浅釉面的亮度输入；没有修改任何单位材质、枪口、光源或共享 shader。

新增 `core_coolant.mesh` / `core_interlock.mesh` 直接调用 `core()` 并重映射材质：灰蓝冷却立柱与金属冠、冷蓝灰联锁立柱与上冠，管线颜色随所属设施轻微区别。两者均为 1696 个三角形，bounds 为 `(-1.7,0,-1.7)` 至 `(1.7,3.7,1.7)`，全部顶点属性及各组索引和 `core.mesh` 逐项相同。可在场景原核心位置替换网格，不需要更改碰撞、导航或状态环挂点。
